# TextField to Input Migration

See the [v8 component migration inventory](/docs/concepts-migration-from-v8-component-mapping--docs).

## Overview

Use [Input](/docs/components-input--docs) for single-line `TextField` scenarios in Fluent UI v9. The v9 component is intentionally smaller than v8 `TextField`: labels, hints, required state, and validation messaging move into [Field](/docs/components-field--docs), while multiline scenarios move to the separate [Textarea migration guide](/docs/concepts-migration-from-v8-components-textarea-migration--docs).

## Component mapping

| v8 scenario                                | v9 destination                             | Notes                                                                                              |
| ------------------------------------------ | ------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| Single-line `TextField`                    | `Field` plus `Input`                       | Use `Field` when the v8 control supplied `label`, `description`, `errorMessage`, or `required` UI. |
| Multiline `TextField`                      | `Field` plus `Textarea`                    | `Input` does not support `multiline`, `rows`, or `autoAdjustHeight`.                               |
| `prefix`, `suffix`, `iconProps` adornments | `Input` `contentBefore` and `contentAfter` | Slot content is rendered inside the control chrome instead of through dedicated string props.      |

## What changed

V8 `TextField` bundled layout, labeling, validation, and the input element in one component. In v9, `Input` is the text-entry primitive and `Field` provides the surrounding form-field structure. Slot-based adornments replace the v8 prefix, suffix, and icon props, and controlled updates now read the latest value from `data.value` instead of a second `newValue` string argument.

## Architecture and behavior

Treat `Input` as the control and `Field` as the form-field shell. `Field` owns the visible label, required indicator, hint text, validation message, and `aria-*` wiring for the nested control. `Input` owns the native `<input>` props, appearance, size, and `contentBefore` or `contentAfter` slots. If the old `TextField` was multiline, that behavior does not stay on `Input`; migrate it to `Textarea` and keep the same `Field` composition around it when you need labeling or validation UI.

## Prop mapping

| v8 `TextField` prop | v9 replacement                                                | Replacement category    | Migration notes                                                                                                    |
| ------------------- | ------------------------------------------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `label`             | `Field label` or a separate `Label`                           | Composition replacement | `Input` does not render its own label.                                                                             |
| `description`       | `Field hint`                                                  | Composition replacement | `Field` connects hint text through `aria-describedby`.                                                             |
| `errorMessage`      | `Field validationMessage`                                     | Composition replacement | Pair with `validationState` to control the message semantics and styling.                                          |
| `required`          | `Field required`; optionally native `Input required`          | Composition replacement | `Field required` adds the asterisk and `aria-required`; native `required` keeps browser form validation.           |
| `multiline`         | Use `Textarea`                                                | Separate component      | `Input` is single-line only.                                                                                       |
| `rows`              | Use `Textarea rows`                                           | Separate component      | `rows` is only available on `Textarea`.                                                                            |
| `autoAdjustHeight`  | No `Input` equivalent                                         | Unsupported             | Re-evaluate the scenario with `Textarea`; v9 `Input` has no auto-height behavior.                                  |
| `canRevealPassword` | No direct prop                                                | Composition replacement | Use `type="password"` and compose any reveal button yourself, typically in `contentAfter`.                         |
| `iconProps`         | `contentBefore` or `contentAfter`                             | Composition replacement | Supply JSX such as an icon component instead of an `IIconProps` object.                                            |
| `prefix`            | `contentBefore`                                               | Composition replacement | Presentational text or icons render in the slot and are not part of the field value.                               |
| `suffix`            | `contentAfter`                                                | Composition replacement | Use slot content instead of a dedicated string prop.                                                               |
| `onRenderLabel`     | Compose with `Field`, `Label`, or custom JSX                  | Composition replacement | There is no v9 render callback on `Input`.                                                                         |
| `onChange`          | `onChange(event, data)`                                       | Behavioral change       | Read the next value from `data.value`.                                                                             |
| `componentRef`      | `ref`                                                         | Rename                  | V9 refs target the underlying `<input>` element rather than the v8 `ITextField` API surface.                       |
| `styles`            | `className`, `input={{ className: ... }}`, and Griffel styles | Composition replacement | Style the root slot with `className` and the native input through the `input` slot props.                          |
| `theme`             | `FluentProvider`                                              | Composition replacement | Theming is provided by context instead of a per-instance prop.                                                     |
| `underlined`        | `appearance="underline"`                                      | Behavioral change       | The appearance is a string union on `Input`.                                                                       |
| `borderless`        | No direct prop                                                | Behavioral change       | Choose an `appearance` value that matches the design intent, or add custom styling when design review approves it. |

## Styling and theming

Use Griffel classes with Fluent v9 design tokens for any migration-specific layout or adornment styling. `Input` styling is split between the root `className` and the `input` slot props, while `Field` handles label, hint, and validation layout. Theme changes move to `FluentProvider`, and appearance changes use the v9 `appearance` union instead of v8 booleans such as `underlined` or `borderless`.

## Accessibility

Prefer `Field` when the control needs a visible label, hint, or validation message so those relationships are wired correctly through `aria-labelledby` and `aria-describedby`. Decorative slot content in `contentBefore` or `contentAfter` should not replace the accessible name, and any interactive content placed in a slot must carry its own accessible label. When you rely on the browser's required-field behavior, keep the native `required` prop on `Input` in addition to `Field required`.

## Unsupported scenarios and known gaps

MC-4: A multiline `TextField` does not migrate to `Input`; move that scenario to [Textarea](/docs/components-textarea--docs) and use the [Textarea migration guide](/docs/concepts-migration-from-v8-components-textarea-migration--docs) for `rows`, resize, and multiline composition details.

Built-in password reveal is also not part of `InputProps`, so any reveal affordance must be composed manually with a standard button or icon slot.

| MC-2 | Prefix, suffix, and icon APIs move to `contentBefore`/`contentAfter` slots |
| MC-3 | `onChange` now reads `data.value`                                          |
| MC-4 | Multiline `TextField` migrates to `Textarea`, not `Input`                  |
