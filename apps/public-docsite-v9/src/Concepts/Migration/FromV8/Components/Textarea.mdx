# Textarea Migration

See the [v8 component migration inventory](/docs/concepts-migration-from-v8-component-mapping--docs).

## Overview

Use [Textarea](/docs/components-textarea--docs) when a v8 `TextField` relied on `multiline`. The v9 model is explicit: single-line text entry uses [Input](/docs/components-input--docs), multiline entry uses `Textarea`, and surrounding label or validation UI comes from [Field](/docs/components-field--docs).

## Component mapping

| v8 scenario                                      | v9 destination               | Notes                                                                                                                                                                     |
| ------------------------------------------------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TextField multiline`                            | `Field` plus `Textarea`      | `Textarea` is always multiline, so the v8 `multiline` switch becomes the component choice itself.                                                                         |
| `TextField multiline` with `rows` or `resizable` | `Textarea rows` and `resize` | Pick the `resize` string union explicitly in v9.                                                                                                                          |
| Single-line `TextField`                          | `Field` plus `Input`         | Use the [Input migration guide](/docs/concepts-migration-from-v8-components-textfield-to-input-migration--docs) instead of forcing a single-line case through `Textarea`. |

## What changed

V8 exposed single-line and multiline entry from the same `TextField` component. In v9, multiline entry is a distinct component with its own slot model and `resize` prop. Labels, hints, and validation messages move to `Field`, and controlled change handlers now read the next value from `data.value`.

## Architecture and behavior

`Textarea` is the primitive textarea control in Fluent UI v9. It owns native textarea props such as `rows`, `value`, `defaultValue`, and `readOnly`, plus the v9 `appearance`, `size`, and `resize` options. Compose it with `Field` when the old `TextField` used `label`, `description`, `required`, or `errorMessage`. Unlike v8 `TextField`, there is no `multiline` toggle to flip on or off after the fact, and there is no built-in auto-height or password-reveal scenario on `Textarea`.

## Prop mapping

| v8 `TextField` prop | v9 replacement                                                   | Notes                                                                                                                                         |
| ------------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `label`             | `Field label` or a separate `Label`                              | `Textarea` does not render its own label.                                                                                                     |
| `description`       | `Field hint`                                                     | `Field` wires hint text into the control's description relationship.                                                                          |
| `errorMessage`      | `Field validationMessage`                                        | Add `validationState` when you need warning, success, or non-error messaging.                                                                 |
| `required`          | `Field required`; optionally native `Textarea required`          | Use both when you need the v9 form-field UI and native browser validation.                                                                    |
| `multiline`         | Use `Textarea`                                                   | `Textarea` is the multiline destination; no boolean prop is needed.                                                                           |
| `rows`              | `rows`                                                           | The native rows prop is available directly on `Textarea`.                                                                                     |
| `resizable`         | `resize`                                                         | `resizable={false}` maps to `resize="none"`, while `vertical`, `horizontal`, or `both` opt into resize handles because v9 defaults to `none`. |
| `autoAdjustHeight`  | No direct prop                                                   | Rework the layout or build a custom auto-resize wrapper if that behavior is required.                                                         |
| `onChange`          | `onChange(event, data)`                                          | Read the new value from `data.value`.                                                                                                         |
| `onRenderLabel`     | Compose with `Field`, `Label`, or custom JSX                     | There is no render callback on `Textarea`.                                                                                                    |
| `styles`            | `className`, `textarea={{ className: ... }}`, and Griffel styles | Style the root slot separately from the native `textarea` slot.                                                                               |
| `theme`             | `FluentProvider`                                                 | Theming is handled by context.                                                                                                                |
| `underlined`        | No direct prop                                                   | Choose an `appearance` value or custom styling that matches the intended design.                                                              |
| `canRevealPassword` | No equivalent                                                    | Password scenarios belong on `Input`, not `Textarea`.                                                                                         |

## Styling and theming

Use Griffel with Fluent design tokens for any layout or helper text around `Textarea`, and use slot-level class names when you need to style the root versus the native `textarea`. `resize`, `appearance`, and `size` replace v8's mix of booleans and style overrides, while theme changes move to `FluentProvider`.

## Accessibility

Use `Field` for the visible label, hint text, required indicator, and validation message so `Textarea` receives the right `aria-labelledby`, `aria-describedby`, and `aria-invalid` wiring. If you intentionally omit a visible label, provide an `aria-label` directly on `Textarea`. Resize affordances do not change the accessible name or description, so do not rely on the handle as a cue for the field's purpose.

## Unsupported scenarios and known gaps

MC-4: V8 `autoAdjustHeight` and password-related `TextField` scenarios do not map to `Textarea`; keep those requirements on the [Input migration guide](/docs/concepts-migration-from-v8-components-textfield-to-input-migration--docs) or build custom multiline behavior around `Textarea`.

There is also no prefix, suffix, or icon slot on `Textarea`, so multiline adornments need surrounding layout instead of inline control chrome.
