# OverflowSet → Overflow Migration

## Overview

v8 `OverflowSet` renders explicit `items` and `overflowItems` arrays through callbacks. v9 `Overflow` measures
`OverflowItem` elements and reports which responsive items no longer fit. These are separate concepts:

- Convert v8 `items` into measured `<OverflowItem>` children.
- Keep v8 `overflowItems` as explicit menu-only commands; they are **not** detected by measurement.
- Build one menu containing explicit commands plus measured items for which `useIsOverflowItemVisible(id)` is false.
- Show the trigger when either explicit menu-only commands exist or measured items overflow. Set `hasHiddenItems` when
  explicit hidden commands exist so the overflow manager reserves and reports the trigger.

## Responsive and explicit items

```tsx
import {
  Button,
  Menu,
  MenuItem,
  MenuList,
  MenuPopover,
  MenuTrigger,
  Overflow,
  OverflowItem,
  useIsOverflowItemVisible,
  useOverflowMenu,
} from '@fluentui/react-components';

const commands = [
  { id: 'new', label: 'New', onClick: createDocument },
  { id: 'share', label: 'Share', onClick: shareDocument },
];
const explicitOverflowCommands = [{ id: 'settings', label: 'Settings', onClick: openSettings }];

function ResponsiveMenuItem({ command }: { command: (typeof commands)[number] }) {
  const isVisible = useIsOverflowItemVisible(command.id);
  return isVisible ? null : <MenuItem onClick={command.onClick}>{command.label}</MenuItem>;
}

function OverflowMenuButton() {
  const { ref, isOverflowing } = useOverflowMenu<HTMLButtonElement>();
  const hasExplicitItems = explicitOverflowCommands.length > 0;

  if (!isOverflowing && !hasExplicitItems) {
    return null;
  }

  return (
    <Menu>
      <MenuTrigger disableButtonEnhancement>
        <Button ref={ref} aria-label="More commands">
          More
        </Button>
      </MenuTrigger>
      <MenuPopover>
        <MenuList>
          {commands.map(command => (
            <ResponsiveMenuItem key={command.id} command={command} />
          ))}
          {explicitOverflowCommands.map(command => (
            <MenuItem key={command.id} onClick={command.onClick}>
              {command.label}
            </MenuItem>
          ))}
        </MenuList>
      </MenuPopover>
    </Menu>
  );
}

<Overflow hasHiddenItems={explicitOverflowCommands.length > 0}>
  <div role="toolbar" aria-label="Document commands" style={{ display: 'flex', overflow: 'hidden' }}>
    {commands.map(command => (
      <OverflowItem key={command.id} id={command.id}>
        <Button onClick={command.onClick}>{command.label}</Button>
      </OverflowItem>
    ))}
    <OverflowMenuButton />
  </div>
</Overflow>;
```

Both `Overflow` and `OverflowItem` require exactly one React element child. They clone that child and attach a
measurement ref and props to its root. A custom component used as either child must forward its ref to the measured
HTMLElement and spread the supplied root props; an extra fragment or non-forwarding wrapper breaks measurement.

## Defaults, direction, and trigger placement

v9 defaults are `overflowAxis="horizontal"`, `overflowDirection="end"`, `padding={10}`, `minimumVisible={0}`, and
`hasHiddenItems={false}`. `overflowDirection` selects the end from which measured items are removed. It does **not**
place the menu button.

v8 `overflowSide` controls whether the button is laid out before or after the items while preserving keyboard order.
In v9, place `<OverflowMenuButton />` at the start or end of the single flex child yourself, then choose the matching
`overflowDirection` if items should disappear from that same end. v8 `vertical` maps to
`overflowAxis="vertical"`; update the child layout and `aria-orientation` at the same time.

## Semantics and keyboard behavior

`Overflow` supplies measurement, not application semantics or a focus-management policy. Put the correct role and
accessible name on its single container child (`toolbar`, `menubar`, `tablist`, or no widget role), and implement the
keyboard model required by that role. The Fluent `Menu` owns menu-trigger activation, focus transfer, menu navigation,
Escape, and focus return. The surrounding toolbar/menubar owns navigation among visible commands and the trigger.
Preserve command labels and handlers in both the visible and menu renderings.

## Prop Mapping

| v8 `OverflowSet`         | v9 equivalent                                                    |
| ------------------------ | ---------------------------------------------------------------- |
| `items`                  | Measured `<OverflowItem id="...">` children                      |
| `overflowItems`          | Explicit menu-only items plus `hasHiddenItems`                   |
| `onRenderItem`           | Declarative visible item JSX                                     |
| `onRenderOverflowButton` | `useOverflowMenu` + a composed `Menu`                            |
| `vertical`               | `overflowAxis="vertical"` plus vertical layout/orientation       |
| `overflowSide`           | Trigger location in child layout; optionally `overflowDirection` |
| `styles`                 | `className`/`makeStyles` on the child and item elements          |
| `role`                   | Role on the single container child                               |
| `componentRef.focus*`    | Application refs/focus management                                |

There is no v8 `overflowMenuProps` prop to migrate. Configure the v9 `Menu`, trigger, popover, and list directly.

| v9 API                          | Purpose                                                        |
| ------------------------------- | -------------------------------------------------------------- |
| `useOverflowMenu`               | Trigger ref and whether any responsive/declared items overflow |
| `useIsOverflowItemVisible(id)`  | Whether one measured item is visible                           |
| `useOverflowCount()`            | Number of measured hidden items                                |
| `useIsOverflowGroupVisible(id)` | Visibility state for an item group                             |
| `OverflowItem.priority`         | Higher values overflow later; exclusive with `pinned`          |
| `OverflowItem.pinned`           | Never overflow; exclusive with `priority`                      |
| `OverflowItem.groupId`          | Associates an item with a visibility group                     |
