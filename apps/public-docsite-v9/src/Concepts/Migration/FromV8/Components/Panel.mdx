# Panel / Drawer Migration

v8 `Panel` is controlled via `isOpen` and configured through flat props (`headerText`, `type`, `onRenderFooterContent`).

v9 `Drawer` is composable: content is structured via `DrawerHeader`, `DrawerBody`, and `DrawerFooter` children.
The v9 package exports two variants:

- **`OverlayDrawer`** — floats over content with a backdrop (equivalent to v8 Panel)
- **`InlineDrawer`** — embedded in the layout and pushes content (no v8 equivalent)

## Examples

### Basic Migration

Basic v8 usage:

```tsx
import { Panel, PanelType, PrimaryButton, DefaultButton } from '@fluentui/react';

<Panel
  isOpen={isOpen}
  onDismiss={handleClose}
  type={PanelType.medium}
  headerText="Settings"
  hasCloseButton
  onRenderFooterContent={() => (
    <>
      <PrimaryButton onClick={handleSave} styles={{ root: { marginRight: 8 } }}>
        Save
      </PrimaryButton>
      <DefaultButton onClick={handleClose}>Cancel</DefaultButton>
    </>
  )}
>
  <p>Panel body content</p>
</Panel>;
```

The equivalent v9 usage is:

```tsx
import {
  OverlayDrawer,
  DrawerHeader,
  DrawerHeaderTitle,
  DrawerBody,
  DrawerFooter,
  Button,
} from '@fluentui/react-components';
import { DismissRegular } from '@fluentui/react-icons';

<OverlayDrawer open={isOpen} onOpenChange={(_, data) => setIsOpen(data.open)} position="end" size="medium">
  <DrawerHeader>
    <DrawerHeaderTitle
      action={<Button appearance="subtle" icon={<DismissRegular />} onClick={handleClose} aria-label="Close" />}
    >
      Settings
    </DrawerHeaderTitle>
  </DrawerHeader>

  <DrawerBody>
    <p>Panel body content</p>
  </DrawerBody>

  <DrawerFooter>
    <Button appearance="primary" onClick={handleSave}>
      Save
    </Button>
    <Button onClick={handleClose}>Cancel</Button>
  </DrawerFooter>
</OverlayDrawer>;
```

### InlineDrawer (no v8 equivalent)

Use `InlineDrawer` only when the drawer should remain in the page layout
and push adjacent content. Existing overlaying v8 panels normally migrate to
`OverlayDrawer`.

## Prop Mapping

### PanelType → position + size

| v8 `PanelType`   | v9 `position` | v9 `size`  | Notes                                         |
| ---------------- | ------------- | ---------- | --------------------------------------------- |
| `SmallFixedFar`  | `"end"`       | `"small"`  | Default                                       |
| `SmallFixedNear` | `"start"`     | `"small"`  |                                               |
| `SmallFluid`     | `"end"`       | `"small"`  | Full height; custom width via CSS             |
| `Medium`         | `"end"`       | `"medium"` |                                               |
| `Large`          | `"end"`       | `"large"`  |                                               |
| `LargeFixed`     | `"end"`       | `"large"`  |                                               |
| `ExtraLarge`     | `"end"`       | `"full"`   |                                               |
| `Custom`         | `"end"`       | custom CSS | `style={{ width: '...' }}` on `OverlayDrawer` |
| `CustomNear`     | `"start"`     | custom CSS |                                               |

### IPanelProps → OverlayDrawerProps

| v8                      | v9                                          | Notes                                        |
| ----------------------- | ------------------------------------------- | -------------------------------------------- |
| `isOpen`                | `open`                                      |                                              |
| `onDismiss`             | `onOpenChange`                              | `(ev, data) => data.open === false` on close |
| `type`                  | `position` + `size`                         | See table above                              |
| `headerText`            | `<DrawerHeaderTitle>` children              |                                              |
| `onRenderHeader`        | `<DrawerHeader>` children                   |                                              |
| `hasCloseButton`        | Button in `DrawerHeaderTitle` `action` slot | See example above                            |
| `isBlocking`            | `modalType`                                 | The v8 default (`true`) maps to `"modal"`    |
| `isLightDismiss`        | Controlled `onOpenChange` behavior          | Do not change background interactivity       |
| `onRenderFooterContent` | `<DrawerFooter>` children                   |                                              |
| `onRenderBody`          | `<DrawerBody>` children                     |                                              |
| `onRenderNavigation`    | `<DrawerHeaderNavigation>` children         |                                              |
| `customWidth`           | `style` or `className` on `OverlayDrawer`   |                                              |
| `styles`                | `className` + `makeStyles`                  |                                              |
| `theme`                 | `FluentProvider`                            |                                              |
| `layerProps`            | —                                           | Not supported                                |
| `componentRef`          | `ref`                                       |                                              |

| v9 `modalType` | v8 equivalent                                      | Behavior                                   |
| -------------- | -------------------------------------------------- | ------------------------------------------ |
| `"modal"`      | Default v8 Panel (`isBlocking={true}`)             | Backdrop blocks interaction with the page  |
| `"non-modal"`  | Only experiences that allow background interaction | No backdrop; content behind is interactive |
| `"alert"`      | No ordinary Panel equivalent                       | Reserve for genuinely urgent alert dialogs |

`isLightDismiss` controls whether an outside action dismisses the v8 Panel; it
does not determine whether page content remains interactive. Preserve that
dismissal behavior through controlled `open` and `onOpenChange` handling without
mechanically changing `modalType`.
