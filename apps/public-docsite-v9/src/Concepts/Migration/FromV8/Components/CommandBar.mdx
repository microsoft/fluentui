# CommandBar → Toolbar Migration

## Overview

v8 `CommandBar` is **data-driven**: items are passed as `ICommandBarItemProps[]` arrays —
one for primary items, one for overflow items, one for far-right items.

v9 `Toolbar` is **declarative**: items are JSX children using `ToolbarButton`,
`ToolbarToggleButton`, `ToolbarDivider`, etc. Overflow requires the `Overflow` + `OverflowItem`
pattern from `@fluentui/react-components`.

## Examples

### Basic Migration

Basic v8 usage:

```tsx
import { CommandBar, ICommandBarItemProps } from '@fluentui/react';

const items: ICommandBarItemProps[] = [
  { key: 'new', text: 'New', iconProps: { iconName: 'Add' }, onClick: handleNew },
  { key: 'edit', text: 'Edit', iconProps: { iconName: 'Edit' }, onClick: handleEdit },
  { key: 'delete', text: 'Delete', iconProps: { iconName: 'Delete' }, disabled: true },
];

const farItems: ICommandBarItemProps[] = [
  { key: 'info', text: 'Info', iconProps: { iconName: 'Info' }, onClick: handleInfo },
];

<CommandBar items={items} farItems={farItems} />;
```

The equivalent v9 usage is:

```tsx
import { Toolbar, ToolbarButton, ToolbarDivider } from '@fluentui/react-components';
import { AddRegular, EditRegular, DeleteRegular, InfoRegular } from '@fluentui/react-icons';
import { makeStyles } from '@fluentui/react-components';

const useStyles = makeStyles({ spacer: { marginLeft: 'auto' } });

function MyToolbar() {
  const s = useStyles();
  return (
    <Toolbar>
      <ToolbarButton icon={<AddRegular />} onClick={handleNew}>
        New
      </ToolbarButton>
      <ToolbarButton icon={<EditRegular />} onClick={handleEdit}>
        Edit
      </ToolbarButton>
      <ToolbarButton icon={<DeleteRegular />} disabled>
        Delete
      </ToolbarButton>
      {/* farItems equivalent: push to far end with marginLeft: auto */}
      <ToolbarDivider className={s.spacer} />
      <ToolbarButton icon={<InfoRegular />} onClick={handleInfo}>
        Info
      </ToolbarButton>
    </Toolbar>
  );
}
```

### CommandBarButton → ToolbarButton

`CommandBarButton` maps to `ToolbarButton` when used inside a `CommandBar` / `Toolbar`.
When used standalone (outside a CommandBar), replace with `Button`.

```tsx
// v8
import { CommandBarButton } from '@fluentui/react';
<CommandBarButton iconProps={{ iconName: 'Add' }}>New</CommandBarButton>;

// v9 — inside Toolbar
import { ToolbarButton } from '@fluentui/react-components';
import { AddRegular } from '@fluentui/react-icons';
<ToolbarButton icon={<AddRegular />}>New</ToolbarButton>;
```

### Toggle and Menu Items

Use `ToolbarToggleButton` for checked command items. Checked state belongs to
the root `Toolbar`: each toggle supplies a required `name` and `value`, while
`checkedValues` (controlled) or `defaultCheckedValues` (uncontrolled) contains
the values checked in each named group. `onCheckedValueChange` receives
`{ name, checkedItems }`.

```tsx
import * as React from 'react';
import { Toolbar, ToolbarToggleButton } from '@fluentui/react-components';
import type { ToolbarProps } from '@fluentui/react-components';

const FormattingToolbar = () => {
  const [checkedValues, setCheckedValues] = React.useState<Record<string, string[]>>({
    formatting: ['bold'],
  });
  const onCheckedValueChange: ToolbarProps['onCheckedValueChange'] = (_, { name, checkedItems }) => {
    setCheckedValues(current => ({ ...current, [name]: checkedItems }));
  };

  return (
    <Toolbar checkedValues={checkedValues} onCheckedValueChange={onCheckedValueChange}>
      <ToolbarToggleButton name="formatting" value="bold">
        Bold
      </ToolbarToggleButton>
      <ToolbarToggleButton name="formatting" value="italic">
        Italic
      </ToolbarToggleButton>
    </Toolbar>
  );
};
```

Wrap a `ToolbarButton` in `MenuTrigger` when a v8 item has `subMenuProps`;
render the submenu entries as `MenuItem` children.

For an item with both `split` and `subMenuProps`, use the `MenuTrigger`
render-function form and spread its props onto `SplitButton.menuButton`. Do not
wrap the whole `SplitButton`; its `primaryActionButton` must remain independent
from the menu trigger. See the
[Button migration guide](/docs/concepts-migration-from-v8-components-button-migration--docs)
for the complete composition.

When a `SplitButton` is a peer of `ToolbarButton` controls, give it the same
visual treatment, normally `appearance="subtle"` unless the source gives that
command additional emphasis.

When that split item moves into the overflow menu, preserve both actions with
`MenuSplitGroup`; replacing it with one submenu-only `MenuItem` drops the v8
primary action:

```tsx
import { Menu, MenuItem, MenuList, MenuPopover, MenuSplitGroup, MenuTrigger } from '@fluentui/react-components';
import { ArrowDownloadRegular } from '@fluentui/react-icons';

<MenuList>
  {/* Other overflowed commands */}
  <Menu>
    <MenuSplitGroup>
      <MenuItem icon={<ArrowDownloadRegular />} onClick={downloadDefault}>
        Download
      </MenuItem>
      <MenuTrigger disableButtonEnhancement>
        <MenuItem aria-label="More download options" />
      </MenuTrigger>
    </MenuSplitGroup>
    <MenuPopover>
      <MenuList>
        <MenuItem onClick={downloadPdf}>As PDF</MenuItem>
        <MenuItem onClick={downloadDocument}>As Word</MenuItem>
      </MenuList>
    </MenuPopover>
  </Menu>
</MenuList>;
```

### Icon-only commands

v8 `CommandBar` automatically shows a `TooltipHost` for `iconOnly` items whose
text or tooltip content is defined. Preserve both discoverability and the
accessible name with a v9 tooltip:

```tsx
<Tooltip content="Information" relationship="label">
  <ToolbarButton icon={<InfoRegular />} />
</Tooltip>
```

Do not add a second `aria-label` when `relationship="label"` supplies the
accessible name.

### Overflow Handling

Every `OverflowItem` must receive a DOM element or a component that forwards
the measurement ref and supplied root props. For split-button or menu
compositions, use a real wrapper as the direct child or explicitly forward
those values; do not pass a plain function component that discards them.

Wrap the toolbar in `Overflow`, wrap each measured item in `OverflowItem`,
and compose the overflow menu with `useOverflowMenu` and
`useIsOverflowItemVisible`. Unlike v8, overflow items are detected rather than
provided as a separate static array.

When `farItems` must remain visible, keep them outside the element measured by
`Overflow`. The measured primary region should flex into the space left by the
fixed far-items region:

```tsx
import { Overflow, OverflowItem, Toolbar, ToolbarButton, ToolbarDivider, makeStyles } from '@fluentui/react-components';

const useStyles = makeStyles({
  root: {
    display: 'flex',
    width: '100%',
  },
  primary: {
    display: 'flex',
    flexGrow: 1,
    minWidth: 0,
    overflow: 'hidden',
  },
  farItems: {
    display: 'flex',
    flexShrink: 0,
  },
});

function MigratedCommandBar() {
  const styles = useStyles();

  return (
    <Toolbar className={styles.root} aria-label="Document commands">
      <Overflow>
        <div className={styles.primary}>
          {items.map(item => (
            <OverflowItem key={item.id} id={item.id}>
              <ToolbarButton icon={item.icon} onClick={item.onClick}>
                {item.text}
              </ToolbarButton>
            </OverflowItem>
          ))}
          <OverflowMenuButton items={items} />
        </div>
      </Overflow>

      <ToolbarDivider />
      <div className={styles.farItems}>
        {farItems.map(item => (
          <ToolbarButton key={item.id} icon={item.icon} onClick={item.onClick}>
            {item.text}
          </ToolbarButton>
        ))}
      </div>
    </Toolbar>
  );
}
```

`Overflow` calculates occupied width from registered `OverflowItem` elements,
registered dividers, and its registered overflow-menu trigger. An unregistered
far item placed inside the measured element is visible but is not included in
that calculation, so primary commands can overflow at the wrong widths. Either
use the sibling layout above or register an always-visible command as
`<OverflowItem pinned>` so its width is measured. See the
[Overflow migration guide](/docs/concepts-migration-from-v8-components-overflowset-migration--docs)
for the menu implementation.

## Prop Mapping

### ICommandBarProps → ToolbarProps

| v8                 | v9                                      | Notes                                                                    |
| ------------------ | --------------------------------------- | ------------------------------------------------------------------------ |
| `items`            | `children` (`ToolbarButton`, etc.)      | JSX children replace the items array                                     |
| `overflowItems`    | `Overflow` + `OverflowItem` pattern     | Compose measured items and an overflow menu                              |
| `farItems`         | Fixed sibling region or pinned items    | Keep outside the measured region, or register with `OverflowItem pinned` |
| `buttonAs`         | —                                       | Wrap in `ToolbarButton` directly                                         |
| `overflowButtonAs` | Custom `ToolbarButton` in overflow menu | Use it as the overflow menu trigger                                      |
| `className`        | `className`                             |                                                                          |
| `styles`           | `className` + `makeStyles`              |                                                                          |
| `theme`            | `FluentProvider`                        |                                                                          |

### ICommandBarItemProps → ToolbarButtonProps

| v8 item prop       | v9                               | Notes                                                                                                                                      |
| ------------------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `text`             | `children`                       | Move to JSX children                                                                                                                       |
| `key`              | `key`                            | React key on the JSX element                                                                                                               |
| `iconProps`        | `icon` slot                      | Pass `<IconComponent />`                                                                                                                   |
| `onClick`          | `onClick`                        |                                                                                                                                            |
| `disabled`         | `disabled`                       |                                                                                                                                            |
| `checked`          | `checkedValues` on `Toolbar`     | Use a `ToolbarToggleButton` with `name` and `value`; update the named group in `onCheckedValueChange`                                      |
| `subMenuProps`     | Wrap in `Menu` + `MenuTrigger`   | Render submenu entries as `MenuItem` children                                                                                              |
| `split`            | `SplitButton`                    | Put `MenuTrigger` render props on `menuButton`; see the [Button guide](/docs/concepts-migration-from-v8-components-button-migration--docs) |
| `iconOnly`         | No `children`; wrap in `Tooltip` | Use `relationship="label"` to preserve v8's visible tooltip and accessible name                                                            |
| `ariaLabel`        | `aria-label`                     |                                                                                                                                            |
| `tooltipHostProps` | `Tooltip` props                  | Map content, relationship, positioning, and delays                                                                                         |
| `styles`           | `className` + `makeStyles`       |                                                                                                                                            |

v8 `iconProps.iconName` values use the MDL2 catalog; do not replace them with
one generic icon. Choose the closest semantic Fluent System Icon from
`@fluentui/react-icons` and verify each mapping individually. Common CommandBar
mappings include:

| v8 MDL2 name    | v9 icon                   |
| --------------- | ------------------------- |
| `TeamsLogo`     | `PeopleTeamRegular`       |
| `PDF`           | `DocumentPdfRegular`      |
| `WordDocument`  | `DocumentTextRegular`     |
| `ExcelDocument` | `DocumentTableRegular`    |
| `MoveToFolder`  | `FolderArrowRightRegular` |

These are semantic replacements, not glyph-identical aliases. Preserve
distinct source icons for distinct actions, and consult the current icon
catalog when no direct name appears in this table.
