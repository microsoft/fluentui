# CardFooter Migration

## Overview

Fluent UI v8 provides the `DocumentCardActions` component. Fluent UI v9 provides a more consistent and opinionated `CardFooter` instead.

## Prop Mapping

This table maps `DocumentCard` v8 props to the `Card` v9 equivalent.

| v8           | v9        | Notes                                     |
| ------------ | --------- | ----------------------------------------- |
| className    | className |                                           |
| componentRef | ref       |                                           |
| views        | n/a       | see Migrate `views` prop in this document |
| role         | role      |                                           |
| styles       | className |                                           |
| theme        | n/a       | Use `FluentProvider` to customize themes  |

### Migrate `views` prop

`DocumentCardActions.actions` is required in v8. Recreate every required action
as a v9 `Button` child and preserve its accessible label and handler. The
`views` prop is no longer supported. To migrate it, render a positive count in
the `CardFooter` `action` slot. Give the count an accessible name rather than
relying on the eye icon to communicate its meaning.

Before:

```tsx
import { DocumentCard, DocumentCardActions } from '@fluentui/react/lib/DocumentCard';

const documentCardActions = [
  {
    iconProps: { iconName: 'Share' },
    ariaLabel: 'share action',
  },
  {
    iconProps: { iconName: 'Pin' },
    ariaLabel: 'pin action',
  },
  {
    iconProps: { iconName: 'Ringer' },
    ariaLabel: 'notifications action',
  },
];

export const DocumentCardCompleteExample: React.FunctionComponent = () => (
  <DocumentCard>
    <DocumentCardActions actions={documentCardActions} views={432} />
  </DocumentCard>
);
```

After:

```tsx
import * as React from 'react';
import { Button, Card, CardFooter, makeStyles, shorthands } from '@fluentui/react-components';
import { Pin20Regular, Share20Regular, ServiceBell20Regular, Eye20Regular } from '@fluentui/react-icons';

const useStyles = makeStyles({
  card: {
    width: '300px',
  },

  actions: {
    ...shorthands.gap('4px'),
    ...shorthands.padding('4px'),
    display: 'flex',
    alignItems: 'center',
  },
  visuallyHidden: {
    position: 'absolute',
    width: '1px',
    height: '1px',
    padding: 0,
    margin: '-1px',
    overflow: 'hidden',
    clip: 'rect(0, 0, 0, 0)',
    whiteSpace: 'nowrap',
    border: 0,
  },
});

export const Default = () => {
  const styles = useStyles();
  const views = 432;

  return (
    <Card size="small" className={styles.card}>
      <CardFooter
        action={
          views > 0 ? (
            <span className={styles.actions}>
              <Eye20Regular aria-hidden />
              <span>{views}</span>
              <span className={styles.visuallyHidden}> views</span>
            </span>
          ) : undefined
        }
      >
        <Button appearance="transparent" icon={<Share20Regular />} aria-label="Share document" />
        <Button appearance="transparent" icon={<Pin20Regular />} aria-label="Pin document" />
        <Button appearance="transparent" icon={<ServiceBell20Regular />} aria-label="Manage document notifications" />
      </CardFooter>
    </Card>
  );
};
```

Do not announce a misleading “0 views” value merely to fill the `action` slot;
omit the slot when the value is absent or not positive. If a zero value is
meaningful in the product, render it intentionally with the same accessible
name. Icon-only action buttons always need an `aria-label`.
