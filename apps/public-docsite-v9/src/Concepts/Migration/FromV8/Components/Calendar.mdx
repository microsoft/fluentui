# Calendar Migration

Fluent UI React v9 does not currently have a native replacement for the v8
`Calendar`. Use `Calendar` from `@fluentui/react-calendar-compat` as a migration
bridge. Its API intentionally remains close to v8, while its implementation and
styling integrate with v9.

```tsx
// v8
import { Calendar } from '@fluentui/react';

// v9 compatibility package
import { Calendar } from '@fluentui/react-calendar-compat';
```

Do not import the compatibility component from `@fluentui/react-components`.

## Examples

### Basic Migration

```tsx
// v8
import { Calendar, DayOfWeek } from '@fluentui/react';

<Calendar
  value={selectedDate}
  firstDayOfWeek={DayOfWeek.Monday}
  minDate={minimumDate}
  maxDate={maximumDate}
  onSelectDate={date => setSelectedDate(date)}
/>;
```

```tsx
// v9
import { Calendar, DayOfWeek } from '@fluentui/react-calendar-compat';

<Calendar
  value={selectedDate}
  firstDayOfWeek={DayOfWeek.Monday}
  minDate={minimumDate}
  maxDate={maximumDate}
  onSelectDate={date => setSelectedDate(date)}
/>;
```

### Migration boundary

`CalendarCompat` is the supported bridge for existing calendar experiences, not
a signal to copy v8 styling APIs into new code. Keep app-owned wrappers narrow so
they can be replaced when a native v9 calendar becomes available.

## Prop Mapping

### API mapping

Most behavioral props remain available in the compatibility package.

| v8 `Calendar`                                     | v9 `CalendarCompat`                                            |
| ------------------------------------------------- | -------------------------------------------------------------- |
| `value`, `today`                                  | Same props                                                     |
| `minDate`, `maxDate`, `restrictedDates`           | Same props                                                     |
| `dateRangeType`, `workWeekDays`                   | Same props                                                     |
| `firstDayOfWeek`, `firstWeekOfYear`               | Same props                                                     |
| `strings`, `dateTimeFormatter`                    | Same localization hooks                                        |
| `isMonthPickerVisible`, `isDayPickerVisible`      | Same props                                                     |
| `showMonthPickerAsOverlay`                        | Same legacy overlay behavior                                   |
| `showGoToToday`, `showWeekNumbers`                | Same props                                                     |
| `showSixWeeksByDefault`                           | Same prop                                                      |
| `highlightCurrentMonth`, `highlightSelectedMonth` | Same props                                                     |
| `calendarDayProps`, `calendarMonthProps`          | Same nested customization props                                |
| `componentRef`                                    | Still exposes `ICalendar.focus()`                              |
| `onSelectDate`                                    | Still receives the selected `Date` and optional selected range |
| `onDismiss`                                       | Same callback                                                  |
| `styles`, `theme`                                 | Replace with `className`, `makeStyles`, and v9 design tokens   |

## Accessibility

Continue to provide localized `strings` and `dateTimeFormatter` values. Set
`firstDayOfWeek` and `firstWeekOfYear` according to the user's locale.

`allFocusable` puts disabled dates and controls in the tab order. Preserve it
only when the existing experience specifically depends on that behavior.
