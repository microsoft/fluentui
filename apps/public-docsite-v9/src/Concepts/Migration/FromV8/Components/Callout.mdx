# Callout → Popover Migration

## Overview

v8 `Callout` is a standalone component positioned next to a `target` element (ref or DOM node)
and configured via flat props (`directionalHint`, `isBeakVisible`, `gapSpace`).

v9 `Popover` is **composable**: `PopoverTrigger` wraps the element that opens the popover,
and `PopoverSurface` contains the floating content. This eliminates the need for a `target` ref
in the common case because the trigger/surface relationship is established by co-location in JSX.

## Examples

### Basic Migration

Basic v8 usage:

```tsx
import { Callout, DirectionalHint } from '@fluentui/react';

const targetRef = React.useRef<HTMLButtonElement>(null);
const [isVisible, setIsVisible] = React.useState(false);

<>
  <button ref={targetRef} onClick={() => setIsVisible(true)}>
    Open
  </button>
  {isVisible && (
    <Callout
      target={targetRef}
      onDismiss={() => setIsVisible(false)}
      directionalHint={DirectionalHint.bottomLeftEdge}
      isBeakVisible
      gapSpace={8}
    >
      <p style={{ padding: 16 }}>Callout content</p>
    </Callout>
  )}
</>;
```

The equivalent v9 usage is:

```tsx
import { Popover, PopoverTrigger, PopoverSurface, Button } from '@fluentui/react-components';

<Popover withArrow positioning="below-start">
  <PopoverTrigger disableButtonEnhancement>
    <Button>Open</Button>
  </PopoverTrigger>
  <PopoverSurface style={{ padding: 16 }}>
    <p>Popover content</p>
  </PopoverSurface>
</Popover>;
```

### External target

Prefer `PopoverTrigger`. When the existing target must remain separate from the
popover, set it through `positioningRef` and mark it as the focus restoration
target:

```tsx
import * as React from 'react';
import { Button, Popover, PopoverSurface, useRestoreFocusTarget } from '@fluentui/react-components';
import type { PositioningImperativeRef } from '@fluentui/react-components';

const ExternalTargetPopover = () => {
  const [open, setOpen] = React.useState(false);
  const buttonRef = React.useRef<HTMLButtonElement>(null);
  const positioningRef = React.useRef<PositioningImperativeRef>(null);
  const restoreFocusTargetAttributes = useRestoreFocusTarget();

  React.useEffect(() => {
    if (buttonRef.current) {
      positioningRef.current?.setTarget(buttonRef.current);
    }
  }, []);

  return (
    <>
      <Button
        {...restoreFocusTargetAttributes}
        ref={buttonRef}
        aria-expanded={open}
        onClick={() => setOpen(value => !value)}
      >
        Toggle popover
      </Button>
      <Popover
        open={open}
        positioning={{ positioningRef }}
        onOpenChange={(event, data) => {
          if (event.target !== buttonRef.current) {
            setOpen(data.open);
          }
        }}
      >
        <PopoverSurface aria-label="Popover content">Content</PopoverSurface>
      </Popover>
    </>
  );
};
```

### Focus behavior

By default, `Popover` focuses the first focusable element in `PopoverSurface`
when it opens. Use `trapFocus` when focus must remain inside. When
`inertTrapFocus` is also set, content outside the trap becomes inert according
to standard dialog behavior. These props replace app-owned `FocusTrapCallout`
or `FocusTrapZone` composition; they are not interchangeable with autofocus.

## Prop Mapping

### DirectionalHint → positioning

| v8 `DirectionalHint` | v9 `positioning`  |
| -------------------- | ----------------- |
| `topCenter`          | `"above"`         |
| `topLeftEdge`        | `"above-start"`   |
| `topRightEdge`       | `"above-end"`     |
| `topAutoEdge`        | `"above"`         |
| `bottomCenter`       | `"below"`         |
| `bottomLeftEdge`     | `"below-start"`   |
| `bottomRightEdge`    | `"below-end"`     |
| `bottomAutoEdge`     | `"below"`         |
| `leftCenter`         | `"before"`        |
| `leftTopEdge`        | `"before-top"`    |
| `leftBottomEdge`     | `"before-bottom"` |
| `rightCenter`        | `"after"`         |
| `rightTopEdge`       | `"after-top"`     |
| `rightBottomEdge`    | `"after-bottom"`  |

For `gapSpace`, pass positioning as an object:

```tsx
// v8
<>
  <Callout directionalHint={DirectionalHint.bottomLeftEdge} gapSpace={8} />
  <Popover positioning={{ position: 'below', align: 'start', offset: { mainAxis: 8 } }} />
</>
```

### ICalloutProps → PopoverProps

| v8                          | v9                                       | Notes                                                      |
| --------------------------- | ---------------------------------------- | ---------------------------------------------------------- |
| `target`                    | `<PopoverTrigger>` child                 | Replaces ref-based targeting; trigger is co-located in JSX |
| `hidden`                    | `open` (inverted)                        | Closed popovers unmount; there is no keep-mounted prop     |
| `onDismiss`                 | `onOpenChange`                           | `(ev, data) => data.open === false` on close               |
| `directionalHint`           | `positioning`                            | String or object; see table above                          |
| `directionalHintForRTL`     | —                                        | Logical start/end positioning is RTL-aware                 |
| `gapSpace`                  | `positioning={{ offset: { mainAxis } }}` | Pass positioning as object with `offset`                   |
| `isBeakVisible`             | `withArrow`                              |                                                            |
| `beakWidth`                 | —                                        | Removed                                                    |
| `setInitialFocus`           | Default autofocus                        | Use `trapFocus` only when focus must remain inside         |
| `calloutMaxHeight`          | `style` on `<PopoverSurface>`            | `<PopoverSurface style={{ maxHeight: '...' }}>`            |
| `calloutMaxWidth`           | `style` on `<PopoverSurface>`            | `<PopoverSurface style={{ maxWidth: '...' }}>`             |
| `preventDismissOnScroll`    | `closeOnScroll`                          | Inverted: set `closeOnScroll={!preventDismissOnScroll}`    |
| `preventDismissOnResize`    | —                                        | No direct equivalent; implement the policy in app logic    |
| `preventDismissOnLostFocus` | —                                        | No direct equivalent; test the required focus policy       |
| `coverTarget`               | `positioning={{ coverTarget: true }}`    | Now part of the shared positioning API                     |
| `bounds`                    | `flipBoundary` + `overflowBoundary`      | Set both through the `positioning` object                  |
| `doNotLayer`                | `inline`                                 | Render the popover inline instead of through a portal      |
| `layerProps.hostId`         | `mountNode`                              | Select a specific portal container                         |
| `shouldUpdateWhenHidden`    | —                                        | Closed popovers unmount; keep persistent state outside     |
| `onRestoreFocus`            | Trigger-owned restoration                | External targets use `useRestoreFocusTarget`               |
| `styles`                    | `className` on `<PopoverSurface>`        |                                                            |
| `theme`                     | `FluentProvider`                         |                                                            |
| `componentRef`              | `ref` on `<PopoverSurface>`              |                                                            |
| —                           | `trapFocus`                              | New — moves focus in and traps it                          |
| —                           | `inertTrapFocus`                         | Use with `trapFocus` for standard inert outside content    |

`PopoverTrigger` supplies popup semantics and restores focus automatically.
For a triggerless popover, the external trigger must provide the equivalent
keyboard and ARIA behavior and use `useRestoreFocusTarget`. V9 has no direct
replacement for resize-dismiss or lost-focus-dismiss switches, so preserve
those policies explicitly only when the product still requires them.
