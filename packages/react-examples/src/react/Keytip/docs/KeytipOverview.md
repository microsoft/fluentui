A Keytip is a small popup near a component that indicates a key sequence that will trigger that component. These are not to be confused with keyboard shortcuts; they are instead key sequences to traverse through levels of UI components. Technically, a Keytip is a wrapper around a Callout where the target element is discovered through a 'data-ktp-target' attribute on that element.

To enable Keytips on your page, a developer will add the KeytipLayer component somewhere in their document. It can be added anywhere in your document, but must only be added once. Use the registerKeytip utility helper to add a Keytip. A user will enter and exit keytip mode with a IKeytipTransitionSequence, which is a key with any amount of modifiers (Alt, Shift, etc).

By default, the entry and exit sequence is 'Alt-Windows' (Meta) on Windows and 'Option-Control' on macOS. There is also a sequence to 'return' up a level of keytips while traversing. This is by default 'Esc'.

For plain Alt activation, configure `{ key: 'Alt' }` in `keytipStartSequences` and `keytipExitSequences`, and pass `keytipActivationBehavior` with `consumeActivationEvent: true`. Adding Alt to the sequences alone retains legacy event handling and does not suppress the browser's Alt menu or focus behavior. Keep any existing activation aliases in both sequence lists.

With the activation policy, a standalone Alt tap enters keytip mode only on keyup. Alt keydown records a pending activation without showing keytips or invoking the entry callback. Any other key pressed or released before Alt is released cancels that pending activation. Holding Alt and pressing H or C therefore does not execute a keytip or briefly enter and exit keytip mode; the character event remains available to the application or browser. Explicitly configured legacy activation chords such as Alt+Period still enter on keydown.

After releasing Alt, the activation policy processes sequential keytip characters on keydown after application handlers. Held-Alt keytip execution is not supported. Set `unmatchedInputBehavior: 'exitAndPassThrough'` to dismiss keytips for unmatched input, and `consecutiveActivationBehavior: 'exitAndPassThrough'` to let a second consecutive Alt invocation exit and reach the browser. An Alt invocation after sequential input exits but is consumed when `consumeActivationEvent` is enabled.

Once Alt keydown exits keytip mode, configured aliases such as Alt+Period and Alt+Meta cannot reenter during that same Alt gesture. Configured exit chords follow `consumeActivationEvent`, with cancellation decided before `onExitKeytipMode` runs. Return navigation, including Escape at the root, is consumed independently of this setting.

Plain left and right Alt presses use the same activation policy. Right Alt is not excluded based on its physical location; AltGraph, Ctrl+Alt, and composition input remain excluded to preserve international text entry.

All activation-policy behavior is opt-in through `keytipActivationBehavior`, including the additional event listeners, gesture bookkeeping, lifecycle cleanup, and the `enabled` prop. Without the policy, legacy transition and keypress handling remain unchanged. The host can add or remove the policy at runtime; removing it dismisses active keytips and disposes the policy's listeners and gesture state.

With `consumeActivationEvent: true`, the layer consumes the initial Alt keydown and its corresponding keyup to suppress browser chrome behavior, including when another key cancels pending entry. It does not consume the intervening character event. On a standalone tap, the keyup is canceled before `onEnterKeytipMode` runs, so the host can transfer focus to the ribbon within the same document after release. Entry permission is checked again on keyup; blur, composition, disabling, disposal, and policy removal clear pending entry. The layer does not select a ribbon tab or manage application focus itself. If an application moves focus between frames, its integration must handle the original native keyboard events in each relevant frame; keyboard events do not bubble between documents. Programmatically entering keytip mode does not cancel an Alt event that the layer never received.

Fluent UI React components that have keytips enabled have an optional 'keytipProps' prop which handles registering, unregistering, and rendering of the keytip. The keySequences of the Keytip should be the full sequence to get to that keytip. There is a 'buildKeytipConfigMap' helper which will build a map of ID -> IKeytipProps to assist in defining your keytips.
