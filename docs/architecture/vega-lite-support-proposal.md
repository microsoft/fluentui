> **Implementation update — 2026-10-11:** A substantial native P0–P2 subset is now implemented in the working tree, including strict tooltip-array field-bound predicates, targeted composed shared-scale conflict diagnostics, and ranged/center axis-group suppression. The latest recorded gates are **1,507 Vega tests / 29 snapshots passed**, **2,351 full-package tests / 321 snapshots passed, 84 skipped, zero failures**, and passing package production/test types, quiet lint, API generation and live scoped build. Locked dependency restoration resolved the Gauge icon mismatch without manifest/lockfile changes or weakened snapshot assertions. The dependency-inclusive build is **not green**: 26 of 27 dependency tasks succeeded; unchanged baseline `react-overflow:build` API extraction remains blocked. The current contract, ordinary-native axis-null gap, **23 official-grammar-checked fixtures**, focused checks (**396 diagnostics / 124 corpus / 7 tooltip integration tests passed**), and final recorded gate qualifications are in [Vega-Lite semantic fidelity](vega-lite-semantic-fidelity.md). This is not completion of every roadmap item or arbitrary Vega-Lite compatibility. The research/proposal body below is preserved as the historical pre-implementation baseline; its “current support,” test counts, and “no implementation” statements describe that earlier snapshot, not today's implementation.

## 1. Recommendation

Improve the **Vega-Lite grammar and semantics supported by the native Fluent adapter**, rather than treating this as an npm upgrade. Keep native Fluent rendering as the default. Prioritize:

1. Explicit compatibility diagnostics and correct data semantics, especially aggregates, windows, time units, and unsupported marks.
2. The two new 6.5.0 grammar features: parameterized exponential aggregates and field-level tooltip filtering, including matching accessible descriptions.
3. Offset/ranged geometry, stack ordering, and composition/scale resolution.
4. Parameter-driven interactions and accessible exploration, after establishing a properly scoped view/data model.

Run a separate, time-boxed comparison with the official compiler/runtime as a **development oracle** and possible **opt-in companion backend**. Do not silently change renderer, load remote data, or claim full v5/v6 compatibility.

### Evidence and scope

`VegaDeclarativeChart` consumes `chartSchema.vegaLiteSpec`, maps specs to Fluent components, and does not execute compiled Vega. A v6 `$schema` string being accepted does **not** establish v6 semantic compatibility. Raw Vega specs are a different grammar and are not supported by this component.

The audit covers the local type model, adapter, expression evaluator, renderer, responsive wrapper, tests, and recent upstream releases. It is not an exhaustive differential execution of every upstream example. “Implemented” below means the stated subset has source support; it never means complete Vega-Lite parity. Unknown combinations require reference and rendering tests. No overall percentage is assigned because channel, transform, and composition fidelity interact.

**Local baseline executed:** `yarn nx run react-charts:test --testPathPatterns=Vega --runInBand --colors=false --skip-nx-cache`: **3 suites passed; 198 tests passed, 3 skipped; 29 snapshots passed**. These are local behavior tests, not an upstream conformance certificate.

Recent native work is relevant: initial Vega-Lite support landed in `26229a9532` (2026-03-02); expression parsing in `bd7fdfb3ed` (2026-03-10); additional prototype hardening in `5aed6562e0` (2026-09-16); expression hardening in `8d97381631` (2026-10-08).

### Scales, formatting, resilience, and accessibility

- Explicit numeric y domains, `zero: false`, y logarithmic routing, categorical ordering, some axis formats/ticks, titles, and color ranges have mappings. See [scale/format helpers](../../packages/charts/react-charts/library/src/components/VegaDeclarativeChart/VegaLiteSchemaAdapter.ts#L1039-L1170). `sort.field` is not represented by the generic category-order conversion. UTC, pow/sqrt/symlog, reverse, date-time object/union/signal domains, and full axis/legend/config precedence are not complete merely because their types exist.
- Zero/center/normalized stack choices are not uniformly respected across bar/area adapters. A [normalized area](../../packages/charts/react-charts/library/src/components/VegaDeclarativeChart/VegaLiteSchemaAdapter.ts#L3046-L3085) must not be declared conformant until its normalized values and requested axis format have been compared to upstream.
- Container resize already works through [ResizeObserver](../../packages/charts/react-charts/library/src/components/ResponsiveContainer/ResponsiveContainer.tsx#L22-L62) and the [responsive HOC](../../packages/charts/react-charts/library/src/components/ResponsiveContainer/withResponsiveContainer.tsx#L12-L41). Full Vega-Lite `autosize`, width/height step sizing, zero dimensions, and composed-view sizing remain separate concerns.
- Expressions use a [restricted recursive-descent evaluator](../../packages/charts/react-charts/library/src/components/VegaDeclarativeChart/VegaLiteExpressionEvaluator.ts#L1-L91), not arbitrary JavaScript execution. Recent hardening and JSON-depth checks are strengths to retain. They are not a substitute for semantic validation or row/expression/transform-work budgets.
- Native charts supply keyboard/ARIA behavior, but the Vega adapter does not have a general requested-tooltip/description model, selection grammar, or accessible data-exploration tree. The [skipped warning tests](../../packages/charts/react-charts/library/src/components/VegaDeclarativeChart/VegaLiteSchemaAdapterUT.test.tsx#L1062-L1145) explicitly demonstrate that unsupported-feature diagnostics are not currently emitted.
- Header TODOs are stale in places: they still list bar/area/transforms/concat as future work despite existing implementations. The published support contract should be generated from capabilities plus tests, not those comments.

Cover encoding and transform forms; preserve parameter 0.                               |
| Tooltip field filtering, [#9876](https://github.com/vega/vega-lite/pull/9876)    | Unsupported tooltip grammar                               | Implement requested field definitions first, then per-field filtering and shared tooltip/ARIA projection.                                                           |

| Quantitative `yOffset` direction matches y, #9817                                | `yOffset` unsupported                                     | Add channel and directionality semantics when implementing offset geometry.                                                                                         |
| Evaluate signals in unioned scale domains / TypeScript upgrade, #9922            | No reactive union-domain evaluation                       | Treat as unsupported-domain diagnostics now; add scoped parameter-domain evaluation later. Upstream compiler-tooling changes alone are not local semantic features. |
| Initialize animation selections on first pulse, #9900                            | No animation-selection engine                             | Future animation acceptance must include first-frame data, not only subsequent ticks.                                                                               |
| Simpler compilation of explicit datetime domains, #9875                          | No Vega codegen; date parsing only partial                | Compiler-output simplification is not applicable; test datetime-domain semantics separately.                                                                        |
| Escaped fields in point selections, #9904                                        | No point-selection grammar                                | Use a common own-property-safe field resolver across data and future selections.                                                                                    |
| Ungroup offset path marks / revert prior change, #9822                           | No general offset path rendering                          | Preserve path grouping/order explicitly when adding ranged/offset marks; keep a version-pinned regression corpus.                                                   |

**Exact new grammar matters:** exponential aggregates are objects, e.g. `aggregate: { exponential: 0.5 }`, and transform operations can use `op: { exponentialb: 0.5 }`. Bare strings are not substitutes. Tooltip filtering is `tooltip: false` on an encoding field definition, or a `filter` predicate on an explicit tooltip-array entry. Its predicate is bound to that entry's field, without another `field` or `timeUnit` property. Filtered/omitted fields also disappear from generated ARIA descriptions. It is not a row-filter transform and is not an `exclude` list. See the [tagged tooltip specification](https://raw.githubusercontent.com/vega/vega-lite/v6.5.0/site/docs/tooltip.md) and [aggregate documentation](https://vega.github.io/vega-lite/docs/aggregate.html#exponential).

The [ecosystem inventory](https://vega.github.io/vega-lite/ecosystem.html) also lists Deneb/Power BI, notebooks, dashboard editors, and spec-generating tools. This argues for explicit interchange and dialect validation, not claims that all those integrations work with our current subset.

## 5. Proposed architecture and delivery order

### A. Compatibility contract and normalized intermediate model (first)

- Define a versioned **Fluent Vega-Lite capability profile**. Maintain a table by grammar feature and supported combination; avoid a single “supports Vega-Lite 6” checkbox.
- Add an **opt-in strict validation/diagnostic path** returning stable codes, spec paths, severity, and a remedy. Example categories: unsupported mark/channel/transform, approximated statistics, unresolved dataset, ignored scale/tooltip setting. Reuse this output in docs and Storybook.
- Preserve the current API/types and default rendering contract. Additive types and options only; deprecate public alternatives before any removal. Do not abruptly make all previously tolerated specs throw in a patch release.
- Normalize without mutating caller encodings/data. Resolve field names, inheritance, grouped keys, derived fields, aggregate op/parameter, and composition paths into an internal representation before choosing a renderer.
- In strict mode, unknown aggregate/window operations must not become count/rank; failed filters must not silently retain all rows. Preserve legacy behavior only as an explicit compatibility path with diagnostics.
- Create one shared aggregate/predicate/field implementation used by encoding aggregates, transforms, tooltip fields, and later selections. Merely extending the public type union is insufficient.

### C. Official runtime: a separate decision, not a prerequisite upgrade

Compare three approaches on a fixed fixture corpus:

| Option                                                                     | Benefit                                                                   | Cost / risk                                                                                          | Recommendation                                                                                            |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Native adapter + shared semantic utilities                                 | Existing Fluent rendering/theming/accessibility, narrow shipped footprint | Ongoing grammar implementation and conformance ownership                                             | Default path for existing supported dashboards.                                                           |
| Official compiler used only for schema checks/reference results in tooling | Independent expected data/layout semantics; release tracking              | ESM/tooling compatibility and security/resource isolation                                            | Establish this oracle early; no automatic shipped dependency.                                             |
| Optional official compiler + Vega runtime backend                          | Much broader grammar, selections, maps, nested views                      | Different visual/keyboard contract, lifecycle, SSR/ESM, CSP, resources, bundle and performance costs | Time-box a proof of concept; explicit opt-in companion boundary only after measurements and partner need. |

For the oracle, use Vega-Lite **6.5.0** with its compatible Vega runtime (**`^6.4.0`** per the [tagged package metadata](https://raw.githubusercontent.com/vega/vega-lite/v6.5.0/package.json)); pin exact tested versions in the harness. The current tag requires Node >=22. Also retain a version-pinned v5 fixture baseline for migration. Never infer download/ship cost from an unpacked npm package size: measure incremental production bundles and startup/interaction costs.

## 6. Verification strategy

1. **Spec corpus:** examples for every row in the 6.5 matrix, existing supported specs, and actual Altair-generated specs with named data/params/composition. Reference version and expected support/diagnostic travel with each fixture.
2. **Differential data tests:** compare transform rows, grouped statistics, derived fields, and domains with the pinned compiler/runtime. Do not compare only snapshots of props or array lengths. Account for numerical tolerances and deterministic random seeds where relevant.
3. **Rendering tests:** assert geometry/order/callout contents/ARIA and add visual regression for ranges, offsets, corners, normalized stacks, first-frame animation, and resize. Exact Vega typography/palettes are not a parity requirement when intentional Fluent styling differs.
4. **Interaction tests:** distinguish focus, hover, click, brush, selection scope and reset. Verify shared/independent views do not accidentally share state or IDs.
5. **Security tests:** retain own-property and callable-value hardening; exercise malicious/invalid expressions, grouped keys, input immutability, cycle/depth/work budgets, remote resources and CSP. Reference runtime execution uses trusted/sandboxed fixtures only.
6. **Performance tests:** measure transformation time and rerenders separately from paint; test representative small/large datasets and series counts. Evaluate worker/offload only after profiling, including repeated transformations on legend/schema updates.
7. **Release gates:** Nx tests/type-check/lint, API report and Beachball for published changes, SSR/React compatibility, accessibility review, and bundle tracking. New behavior and intentional differences must update the capability profile and examples together.

### Non-goals for this research change

- No implementation files, package manifests, lockfiles, public APIs, or snapshots changed.
- No claim of complete Vega-Lite v5/v6 or raw Vega compatibility.
- No automatic runtime fallback, new external requests, or removal of existing functions/types.
- No benchmark results or full upstream differential runs claimed: this session ran the existing native Vega suites and audited source/release notes only.
